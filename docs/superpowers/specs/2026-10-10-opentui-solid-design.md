# OpenTUI + SolidJS 전환 설계

## 목적과 승인된 범위

기존 lgnh의 기능을 유지하면서 OpenTUI + SolidJS 기반 통합 터미널 앱으로 전환한다.
TTY에서 인자 없이 `lgnh`를 실행하면 홈 화면으로 진입하고, 기존 명령은 해당 기능으로 직접 진입하는 경로로 유지한다.
TypeScript와 Bun을 유지하며 Zig 코드를 직접 작성하지 않는다.

이전 세션에서 선택한 기술 조합은 `@opentui/core`, `@opentui/solid`, `solid-js`다.
이번 대화에서 사용자가 통합 TUI와 기존 명령을 함께 유지하는 접근법 및 아래 설계를 승인했다.
이 문서는 구현 전 설계이며, 문서 자체의 사용자 검토와 구현 계획 승인 전에는 제품 코드를 변경하지 않는다.

## 현재 구조와 재사용 경계

- `bin/lgnh-cli.ts`: Bun 실행 진입점.
- `src/main.ts`: 명령 분기, Clack 로그, 커밋 실행 순서, 번역 모드, 자체 ANSI 입력 및 클립보드 처리.
- `src/git.ts`: 프로젝트 검증, staging/diff, commit, push, `StepError`.
- `src/omp.ts`: 커밋 메시지 생성, 번역, 토큰 분석, 모델 fallback 및 실제 사용 모델 반환.
- `src/config.ts`: 설정 파일 경로, 모델 조회·저장 및 fallback 후보.
- `package.json`: 개발 실행, 검사, 단일 바이너리 빌드 및 배포.

Git·OMP·설정 동작과 커밋 메시지·번역 프롬프트는 재사용한다.
커밋 실행 순서만 UI 독립적인 공통 함수로 추출하여 TUI와 비대화형 명령이 공유한다.
Clack, picocolors 및 `ttyInput`, `charWidth`, ANSI 커서 이동·키 시퀀스 파싱은 전환 완료 시 제거한다.
호환용 옛 입력기나 두 번째 커밋 파이프라인을 남기지 않는다.

## 진입 및 호환 계약

- stdin과 stdout이 모두 TTY인 환경의 `lgnh`: 통합 홈 화면.
- 인자 없이 실행한 비TTY 환경: 텍스트 도움말. 입력 대기나 렌더러 생성 없음.
- `lgnh commit`, `commit-fast`, `commit-push`, `commit-fast-push`: 기존 검증·편집·push 옵션을 보존하고 즉시 실행한다. TTY에서는 커밋 화면, 그 외에는 일반 텍스트 진행 출력.
- `lgnh tr` 및 `lgnh translate`: 동일한 번역 진입 경로. TTY에서 입력이 없으면 여러 줄 입력 화면, 인자나 stdin이 있으면 한 번 번역한다.
- `lgnh tr -i` 및 `--interactive`: TTY에서는 반복 번역·복사·다음 입력 모드. 기존과 같이 인자 텍스트로 첫 번역을 시작할 수 있다.
- stdout이 비TTY인 번역: 번역 결과만 stdout에 출력한다. 진행 상태나 ANSI 제어 코드를 섞지 않는다.
- stdin만 파이프인 경우에도 TUI를 만들지 않고 기존 stdin 텍스트를 번역한다.
- `config`, `model`, `model <id>`: 기존 텍스트 출력과 설정 저장을 유지한다. 통합 설정 화면은 별도 진입 경로다.
- `help`, `--help`, `-h`: 텍스트 도움말. 알 수 없는 명령의 현재 도움말 동작을 유지한다.

TTY의 직접 실행은 완료 후 원래 터미널 화면으로 돌아온다.
일회성 번역 결과, 커밋 메시지와 최종 성공 상태는 복원 후 출력하여 화면 종료로 결과가 사라지지 않게 한다.
비대화형 실패는 stderr와 실패 종료 코드로 전달한다.

## UI 구성

### 앱과 홈

하나의 렌더러와 Solid 루트가 화면 전환과 자원 수명을 소유한다.
홈은 번역, 커밋, 설정을 키보드로 선택하는 메뉴이며 실제 작업을 자동 실행하지 않는다.
통합 모드에서는 화면에서 홈으로 돌아갈 수 있고, 직접 명령 모드에서는 작업 완료 시 종료한다.
공통 헤더는 현재 기능과 모델, 하단은 해당 화면의 단축키를 표시한다.
외부 라우터나 전역 상태 라이브러리 없이 Solid signal/store와 컴포넌트 props를 사용한다.

### 번역

OpenTUI textarea를 사용해 여러 줄 입력, 커서 이동, 삭제, 붙여넣기 및 한글·이모지 폭 처리를 맡긴다.
입력 내용과 결과를 분리하고 결과에는 스크롤 영역을 사용한다.
Enter 및 Shift+Enter는 줄바꿈, Cmd+Enter와 Ctrl+Enter는 번역 제출이다.
빈 입력은 요청하지 않고, 요청 중에는 중복 제출을 막는다.

통합 모드와 `tr -i`는 번역 후 결과 복사와 다음 입력을 제공한다.
기존 결과 단계의 `c`/`a`/`q` 및 한글 키 대응도 유지하되, 편집 중 입력 문자를 액션으로 소비하지 않는다.
현재 번역 결과만 보관하며 영구 대화 기록이나 응답 스트리밍은 추가하지 않는다.
일회성 `tr`는 번역 결과를 터미널 복원 후 출력하고 종료한다.

### 커밋

통합 모드에서는 검증 여부, push 여부, 외부 편집기 사용을 선택하고 명시적인 실행 동작으로 시작한다.
화면 진입만으로 staging, commit 또는 push를 수행하지 않는다.
직접 명령은 전달한 옵션으로 즉시 기존 실행 순서를 수행한다.

검증, staging/diff, 메시지 생성, commit, 선택적 push 순서를 유지한다.
각 단계의 상태와 완료 시 소요 시간을 표시하고, 토큰 수, 모델 fallback, 실제 사용 모델 및 생성 메시지를 표시한다.
검증 실패·변경 없음·OMP 실패·commit 실패·push 실패를 서로 구분한다.
commit 이후 push가 실패하면 이미 생성된 commit을 실패로 숨기거나 재실행하지 않는다.

### 설정

현재 모델과 설정 파일 경로를 표시하고 모델 ID를 편집·저장한다.
기존 `loadConfig`, `saveConfig`, `getModel`을 사용하고 새 설정 파일이나 설정 스키마를 만들지 않는다.
저장 실패는 화면에 표시하며 성공한 것처럼 처리하지 않는다.

## 공통 실행 및 오류 처리

커밋 공통 함수는 옵션과 진행 콜백을 받아 결과를 반환한다.
진행 정보는 단계, 상태, 완료 소요 시간, 모델 및 토큰 분석처럼 의미 있는 데이터로 전달하고 ANSI 문자열이나 UI 객체를 전달하지 않는다.
TUI는 해당 데이터를 반응형 상태에 반영하고, 일반 CLI는 텍스트로 출력한다.
번역은 기존 `translateText` 및 fallback 콜백을 그대로 사용한다.

하나의 앱에서 작업은 한 번에 하나만 실행한다.
작업 중에는 중복 실행과 다른 화면으로의 전환을 막고, 실패 후에는 오류 상세를 확인하고 다시 명시적으로 실행할 수 있다.
자동 재시도나 새로운 모델 fallback 정책은 추가하지 않는다.

Ctrl+C 및 종료 신호는 애플리케이션 종료 경로로 모은다.
종료 시 진행 중인 자식 프로세스를 정리하고 렌더러·Solid 루트·등록 이벤트를 해제한다.
종료는 Git 변경을 되돌리는 작업이 아니며 이미 완료된 staging, commit, push를 보존한다.
통합 화면의 작업 실패는 화면 내에서 보여주고, 직접 명령의 실패는 터미널 복원 후 상세와 실패 종료 코드로 전달한다.

`-e`는 렌더러를 suspend하여 터미널 입력·출력 소유권을 외부 Git 편집기에 넘긴다.
편집기 실행이 끝나면 성공·실패와 관계없이 resume하고 그 결과를 처리한다.
정상 종료와 예외 종료 모두 `renderer.destroy()`를 수행하고, 설치 버전이 제공하는 종료 완료 API를 기다린 뒤 최종 출력이나 프로세스 종료를 한다.

## 빌드 및 런타임

개발 실행에는 Solid Bun preload와 JSX 설정을 적용한다.
심볼릭 링크로 다른 저장소에서 실행할 때도 등록이 동작하도록 런처에서 preload를 보장하고, TUI 모듈은 필요한 경로에서 지연 import한다.
도움말·모델 조회·비TTY 출력은 렌더러를 초기화하지 않는다.

`tsconfig.json`은 Solid JSX를 지원하고, 빌드는 `@opentui/solid/bun-plugin`과 `Bun.build`의 compile 옵션을 사용한다.
`bun run dev`, `bun run package`, `bun run deploy`의 사용 계약과 `dist/lgnh` 출력 경로를 유지한다.
대상 플랫폼용 네이티브 라이브러리를 바이너리에 포함하여 저장소나 node_modules가 없는 경로에서도 실행한다.
프로젝트에 Zig 툴체인, React, 새로운 명령어 프레임워크를 추가하지 않는다.

렌더러는 상태 변경 기반으로 갱신하고 상시 애니메이션 루프를 추가하지 않는다.
입력 변경으로 결과·진행 기록 전체를 다시 구성하지 않으며, 대용량 diff를 매 키 입력마다 렌더링하지 않는다.
과거 대화의 메모리·한글 처리 시간 추정은 성능 보장으로 사용하지 않는다.

## 검증 및 완료 기준

1. lint와 typecheck를 통과하고 Solid 소스 및 단일 바이너리를 실제 실행한다.
2. 실제 PTY에서 홈 선택, 번역·커밋·설정 진입과 홈 복귀가 동작한다.
3. 한글·이모지 입력, 커서 이동·삭제, 여러 줄 붙여넣기, 제출, 결과 스크롤, 창 크기 변경 및 복사가 동작한다. 빈 입력·중복 제출은 OMP 작업을 만들지 않는다.
4. 일회성 번역과 반복 번역을 실제 OMP로 실행하고, 반복 모드에서는 복사와 다음 입력을 확인한다.
5. stdin 파이프 및 stdout 리다이렉션의 번역 결과와 종료 코드를 확인하고 TUI 제어 코드가 섞이지 않음을 확인한다.
6. 임시 Git 저장소에서 실제 메시지 생성과 commit을 실행하고, 검증·검증 생략·변경 없음 및 실패 결과를 확인한다.
7. 실제 외부 편집기를 PTY에서 실행해 터미널 인계와 복귀를 확인하고, 임시 로컬 bare 원격 저장소로 push를 확인한다.
8. 성공·실패·Ctrl+C 이후 raw mode, 커서 및 터미널 화면이 복원되고 종료한 앱의 자식 프로세스가 남지 않는다.
9. 모델 저장 검증은 임시 `LGNH_CONFIG_PATH`를 사용하고 사용자 설정을 변경하지 않는다.
10. 저장소 밖에서 소스 런처와 `dist/lgnh`를 실행해 preload 및 네이티브 자산 포함을 확인한다.
11. 최소한의 결정적 회귀 검사를 남겨 다중 바이트 입력 또는 작업 상태 전이의 소비자에게 보이는 오류를 잡는다. 단순 전달·소스 문자열·구현 방식 자체는 테스트하지 않는다.
12. README의 설치·실행·빌드 안내를 실제 계약으로 갱신하고 더 이상 사용하지 않는 UI 코드·의존성 및 임시 검증 파일을 제거한다.

PTY 입력은 터미널로 전달된 한글·키 시퀀스를 검증한다.
운영체제 IME의 실제 조합 중 Enter 동작은 PTY 주입만으로 검증했다고 주장하지 않고, 직접 관찰하지 못한 범위는 명시한다.

## 범위 제외

새 명령어 프레임워크, 사용자 플러그인 시스템, 응답 스트리밍, diff 미리보기, 영구 대화 기록, 새로운 인증·모델 정책은 추가하지 않는다.
기존 명령과 데이터 파일의 불필요한 이름 변경, Git 동작 변경 및 관련 없는 리팩터링은 하지 않는다.
